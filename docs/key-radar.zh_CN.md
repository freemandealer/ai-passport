# 声调雷达

AI Passport 离线音乐调性判定应用。按住 OK 哼唱旋律或播放音乐，松开后显示
估计的大小调、备选调性和模板匹配度。分析对象是一段旋律的调性，不是单音调音器。
开发分支为 `feature/pitch-radar`。

## 操作与界面

| 操作 | 行为 |
| --- | --- |
| 按住 OK | 开始新的倾听；按住期间启用麦克风。 |
| 松开 OK | 结束采集，显示调性估计。 |
| 上键 | 取消采集，切换哼唱/音乐模式并清空结果。 |
| 下键 | 取消采集或错误状态，清空并回到待机。 |
| 持续按住 30 秒 | 自动结算；先松开，再按住开启下一次。 |

240 × 320 竖屏采用暗绿色面板、荧光绿文字、雷达环、音量指示和十二音级条，
音级顺序为 C 至 B。电量位于右上角，读数不可用时显示 `--%`。启动直接进入应用。
保留基线 demo 源码供参考，但不编译到本应用中。

建议输入完整的 8–20 秒旋律，至少需要 3 秒实际分析的音频。开头丢弃 128 ms
预热数据以排除编解码器瞬态和缓冲旧数据。哼唱时每个音尽量保持约 0.3 秒。
单个持续音不能确定调性。松开保留结果，再次按住重新采集。即使 OK 的松开事件
尚未到达，切换和清空仍可取消操作。共用 ADC 的按键只能可靠区分单键，
同时按多键不是有效操作。

## 算法与边界

- 哼唱模式使用整数内循环的 [YIN 类音高检测](https://doi.org/10.1121/1.1458024)，
  采样率 16 kHz，范围 65–1060 Hz，约 C2–C6。连续两个窗口音高一致才计入，
  抑制起音和短暂过渡。适用于单人清唱或单旋律乐器。
- 音乐模式使用 4096 点 Q15 FFT、256 ms Hann 窗和 128 ms 步长，
  累计插值后的音级，主要分析约 C2–C7。在音符取整前估计整体偏调，对符合
  已检测到的低频基音之第 2–6 次谐波的峰值降权，以平滑权重替代原来的
  38 音分硬性丢弃边界。新增的低八度可以计入上一版忽略的低音。支持简单的
  多声部素材；鼓点、仅低音、复杂编曲和强泛音
  可能使结果偏移，不具备音源分离能力。
- 两种模式均按有效帧时长累计十二音级分布，与
  [Krumhansl-Kessler 模板](https://music21.org/music21docs/moduleReference/moduleAnalysisDiscrete.html#krumhanslkessler)
  作 Pearson 相关性比较，排序全部 24 个大小调。百分比是模板匹配度，
  **不是判断正确的概率**。
- 少于四个显著音级、有效周期/音调内容不足、时长过短或削波均有明确重试提示。
  最高相关系数小于 0.60，或领先第二候选不足 0.08 时，标记为不确定。
  即使录音干净，关系大小调也可能难以区分。中古调式、转调、非西方音律和
  非调性音乐不在这套 24 调模型的覆盖范围内。
- 以十二平均律、A4 = 440 Hz 为名义基准；音乐模式逐窗估计统一的半音内偏移。
  没有外部校准参考时，恰好偏移半音的情况无法唯一判别。等音调采用升号名称，例如 C# 而非 Db。

频谱音级加权和音准修正的背景资料见
[HPCP](https://essentia.upf.edu/reference/std_HPCP.html) 与
[KeyExtractor](https://essentia.upf.edu/reference/std_KeyExtractor.html)。本应用
在本地实现有界算法，没有引入 Essentia 依赖。

不使用网络、账号、音频播放、录音文件或持久化设置。停止采集时清空原始 PCM
和分析工作区，仅保留供结果显示使用的音级统计。日志不记录原始麦克风数据。
重启后回到哼唱模式。

## 实现与资源

`main/key_analyzer.c`、`pitch_detector.c` 和 `key_control.c` 为可移植逻辑。
`main/main.c` 管理麦克风任务；`main/key_audio.c` 配对管理编解码器初始化、
唤醒、格式设置与休眠；`main/key_ui.c` 管理长期保留的 LVGL 页面。
复用显示、音频、电量和共享总线 BSP。公共事件枚举末尾新增 `BSP_BTN_RELEASE`，
保持已有枚举值，对应按键组件去抖后的松开事件。

按键回调只覆盖单元素邮箱中的完整按住状态与代次编号，避免队列满时丢失松开。
快速重按会使旧采集失效。阻塞 PCM 读取由唯一工作任务分成每次 256 个采样
（标称 16 ms）完成，不会在读取期间休眠编解码器或修改格式。所有应用层 LVGL
操作持有 BSP 锁。除帧数上限外另设实际时间上限。音频错误显示为可重试状态。
实际设备时序仍需测量。

应用固定保留约 31 KB 音频/DSP 工作区和 6 KB 任务栈，不分配整段录音内存。
FFT 系数和常量字体位图存放在 Flash。本机渲染在 24 KB LVGL 池中出现分配失败，
调整为 32 KB 后通过；本机观测分配峰值 21,488 字节。主机与板端的内存碎片和
指针大小不同。继续使用 240 × 20 RGB565 单 DMA 缓冲和最小 8 MB 分区表。
禁用蓝牙，不启动无线协议栈。启动与结果日志输出空闲堆、最大连续块、最大 DSP
耗时、PCM 读取间隙及工作任务栈余量，用于实机验收。

14/20 px 中文字体覆盖 200 个字符，包括所有固定界面文案与可打印 ASCII。
字体来源、许可证、精确哈希、再生成方法和清单位于
[素材说明](../assets/README.zh_CN.md#声调雷达字体)。不接受任意用户或网络文字。
每个文字控件显式选定字体，中央大音名使用 Montserrat 48。字形检查含已知缺字
的反向测试。字形覆盖和本机渲染通过不代表物理屏幕已经验证。

再录制、按住时清空、读取错误恢复和 LVGL 锁。应用音频封装直接配合真实 BSP

另有 84 条声学回归样本，覆盖十二种移调、正负 42 音分偏调、两个音区的强第三/
第五次谐波及低音旋律。旧版首选调匹配 21/84，新版为 84/84，其中包括旧版误判为
G# 小调的 E 大调片段。这是针对问题的合成样本集，不是真实歌曲准确率。用户
没有提供原始歌曲，因此该歌曲的具体结果仍待复测。测试振荡器在帧边界连续。

另运行地址及未定义行为检查。这些测试验证确定性行为，不能代表真实音乐准确率。

## 已修复的故障路径

第一版在录制结束后休眠 ES8311，下一次仅调用 `init` 和 `set_format`。`init`
是幂等初始化，不会唤醒芯片；`set_format` 会拒绝休眠状态。现在应用在配置前
调用 `bsp_audio_wake()`，也支持暂时故障后的重试。回归测试复现了旧版恰好在
第二次录制时失败。

清空和模式切换不再依赖可能因 ADC 事件顺序而过时的 OK 按住标志，而是取消
当前代次、清空全部结果与音级统计，并允许下一次采集。待机界面解释两种模式，
不确定的结果直接标为候选。工作任务增加输入/清空日志，可区分物理按键没有
被识别与应用状态处理失败。用户反馈所有清空操作均无效，实际按键场景仍需
实机确认；没有猜测或修改电压阈值。

2. 反复按住/松开，包括点按和分析时重按，确认不持续误采集、不混入上一段结果或旧音频。
   持续按住超过 30 秒检查自动结算。
3. 重放用户之前被识别成 G# 小调的 E 大调伴奏片段。哼唱已知 C 大调、A 小调旋律
   并移调；音乐模式播放简单终止式，再测试关系大小调
   歧义素材，记录误判。

5. 反复采集检查堆/栈稳定性、看门狗及编解码器恢复。测量处理与界面更新延迟是否小于
   I2S 的 90 ms DMA 余量，以及实际松开延迟、麦克风和时钟精度。
