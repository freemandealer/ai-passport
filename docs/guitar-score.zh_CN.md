# GREEN ROOM：吉他弹唱谱与节拍器

本应用位于 `feature/guitar-score-metronome`，从本地 `main` 硬件基线新建。
已有应用保留在各自原分支。复用 BSP 的显示、ADC 按键、音频和电量接口，重新设计深色绿色
曲谱界面。启动直接进入曲谱，基线 demo 菜单与页面没有编入本应用。

## 通过 Wi-Fi 编辑曲谱

1. 长按确认约 800 ms 进入选曲，选择末尾的「Wi-Fi score editor」，按确认。
2. 手机或电脑连接屏幕显示的 `Guitar-XXXX` 开放热点，无需密码。热点允许一个客户端连接，
   不提供互联网；手机提示时请选择保持连接。
3. 浏览器打开 `http://192.168.4.1`，页面读取已保存文本。可编辑、检查、
   导入或导出 UTF-8 文本，再保存到设备。
4. 保存成功后暂停播放、替换曲库并选中第一首歌。非法曲谱显示错误行号，
   不替换原谱。请求失败时浏览器保留当前编辑内容，便于重试。

服务直接运行在 Passport 上，无需路由器、账号、云端、BLE 配网、外部资源或 API
订阅。重启设备后重新连接热点并刷新网页。本应用不提供自动弹出的强制门户页面。

旧版固件保存的热点密码会被忽略，无需擦除 NVS 即可免密连接。
若手机仍要求密码，请忽略已保存的 `Guitar-XXXX` 网络后重新连接。

## 曲谱格式

```text
---
绿光练习
C
80
C(轻扫) C Am(分解) Am
F F G G
---
小调漫步
Am
70
1 4 V7 1
6 3 7 1
```

每首歌以独立一行 `---` 开始。随后三行严格对应歌名、调号、默认 BPM，
不会解析为和弦，且不能留空。后续每个由空格、制表符或换行分隔的和弦
都占四个四分音符拍。重复写出的和弦保留为独立小节。支持 LF、CRLF 和 UTF-8 BOM。
不允许没有和弦的空歌曲。

| 字段 | 支持内容 |
| --- | --- |
| 调号 | C 到 B，可附升降号，小调附 `m`；例如 F#、Bb、Am、F#m |
| 默认 BPM | 30～120 的任意整数 |
| 和弦根音 | 字母音名、数字级数或罗马级数，可附升降号 |
| 和弦类型 | 大三和弦、m、7、maj7、m7、dim、dim7、m7b5、aug、sus2、sus4、5、6、m6、add9 |
| 显式大和弦 | `maj` 或 `M`；`M7` 等同 `maj7`，`min` 等同 `m` |
| 容量 | 4096 个 UTF-8 字节、16 首歌、总计 512 小节、歌名最多 24 字 |

纯数字级数按自然大调／自然小调推导顺阶三和弦，例如 C 调的 `6` 是 Am，
Am 调的 `1` 是 Am。小调使用**主音为 1**的编号，不是关系大调编号：Am 的 `3` 是 C。
罗马大写显式表示大和弦，小写表示小和弦。Am 的 `V7` 是 E7，C 的 `ii7` 是 Dm7。
数字后缀显式指定类型：C 调用 `2m7` 表示 Dm7，`27` 表示 D7。
升降号相对于所选调式的音阶，例如 C 调的降七级大和弦可写 `bVII`。

一首歌可以混写音名、数字和罗马级数。设备始终显示解析后的和弦名和罗马级数，
保留正确音名拼写，例如 F# 大调的七级根音是 E#。未加注释的和弦显示一种按法：
优先常见开放把位，否则使用可移动指型。图中从左至右是低音 E 到高音 e；
`x` 是闷弦，`o` 是空弦，左侧数字是图示起始品位。圆点表示品位而非手指编号。
默认标准 EADGBE 调弦、不使用变调夹。不支持斜杠转位、歌词、重复简写和变拍，
非法输入会拒绝保存，不会被静默跳过。

歌名支持可打印 ASCII、U+4E00～U+9FEF 汉字，以及 U+3002、U+300A、U+300B、
U+FF01、U+FF08、U+FF09、U+FF0C、U+FF1F 标点（句号、书名号、感叹号、括号、逗号、问号）。
表情和扩展汉字会报歌名错误。长歌名在设备上以省略号缩短，
保存文本中仍保留完整的受支持名称。

使用英文半角括号附上注释：`C(轻扫)` 或 `6 (分解 轻弹)`。注释属于前一个和弦，
不增加拍数或小节。设备显示解析后的和弦名、一个空格和注释内容，隐藏该小节的
和弦图，下方仍显示功能级数。长内容横向滚动。每小节最多一条非空注释、最多 24 字，
支持与歌名相同的字符集。注释内允许空格，首尾空白会被去除；不允许嵌套括号、
注释内换行、缺失括号或在和弦前写注释。

三栏曲谱占据屏幕主体，移除底部按键提示与 NOW/NEXT/THEN 标签。
拉丁和弦名使用 28 px 字体，中文注释为 24 px，功能级数为 20 px。
设备固定文案使用英文（`COUNT-IN`、`TEMPO`、`CLICK VOLUME`、`SELECT SONG`、
`Wi-Fi score editor`），歌名与注释保留用户输入的语言。速度和音量页面不再显示
步进说明及正反拍强弱提示。网页编辑器保留中文说明，并同步当前按键操作。

## 设备操作

| 页面／操作 | 行为 |
| --- | --- |
| 曲谱／上或下 | 前后移动一小节，到首尾停止 |
| 曲谱／双击上 | 跳到第一小节 |
| 曲谱／双击下 | 前进两小节 |
| 任意页面／长按下 | 暂停并进入速度选择 |
| 任意页面／长按上 | 暂停并进入节拍器音量选择 |
| 速度／上或下 | 每次增加或减少 1 BPM，范围 30～120，不循环 |
| 速度／确认 | 应用速度；再按确认，四拍预备后播放 |
| 音量／上或下 | 每次增加或减少 1，范围 0～10，0 为静音 |
| 音量／确认 | 应用音量并返回暂停的曲谱 |
| 曲谱／确认 | 播放、暂停或继续 |
| 任意页面／长按确认 | 暂停并进入选曲 |
| 选曲／上或下 | 选择歌曲或 Wi-Fi 编辑信息入口 |
| 选曲／确认 | 选定歌曲及其默认速度，或显示 Wi-Fi 信息 |
| Wi-Fi 信息／确认 | 返回曲谱 |

单击识别会等待 250 ms 的双击窗口。在速度、音量或选曲页面双击上下键会移动两步。
长按约 800 ms 触发。
每次启动／继续都会先经过一个四拍空小节，然后从所选小节开头播放，
不受暂停时的小节内位置影响。预备时顶栏为空小节，其后显示所选和弦及下一个和弦。
播放时三栏依次为当前、下一个、下下个小节，每四拍向前移动一格。

播放中手动前后移动，会立即从目标小节开头继续；预备时移动会为新的目标小节
重新数四拍。暂停时移动仍保持暂停。最后一个小节完整播放四拍后停止；
再按确认会从曲首四拍预备后重新开始。不自动循环，也不自动切到下一首。

右侧四格每半拍明暗变化：第 1 格亮、第 1 格暗、第 2 格亮、第 2 格暗，依次循环。
暗半拍仍以边框指示当前拍。每个八分音符响一声，包括四拍预备。
四分音符正拍采用更响的 1 kHz 加谐波音色，相邻反拍使用更轻、更短的 2 kHz 音色。
声音与视觉节拍跟随播放与速度，暂停及曲终时停止。音量默认为 5，范围 0～10；
会话内切歌和上传曲谱保留音量，重启恢复 5。不进行麦克风录音。
若编解码器初始化或播放失败，视觉节拍继续可用，状态栏显示 `!AUDIO`，需重启后重试声音。

进入调速页会保留当前精确 BPM，不再对齐到 5 的倍数。
设备上的临时调速仅在当前会话有效，重新选歌或开机会恢复谱中的默认速度。
永久改变默认速度需在网页文本中修改并保存。

## 实现与存储

- `guitar_score` 负责有界文本解析与级数转换，不依赖 ESP-IDF/LVGL。
  `guitar_shapes` 提供 180 种根音／和弦类型的指型。
- `guitar_player` 使用单调绝对时间和整数比例计算边界，95 BPM 等速度
  不会因为逐拍周期取整而累积误差。
- 应用工作任务管理播放；按键回调只入队。独立电量任务避免 I2C 超时拖延节拍计算。
  电量计初始化失败后每五秒重试，不再整次开机永久保留初始失败状态。正常 SOC 每
  15 秒读取；不可用或非法读数显示 `--` 并在五秒后重试。电量计持续缺失时不伪造
  百分比。共享 I2C 总线初始化或任务创建失败仍需排查启动故障。
- `guitar_metronome` 计算八分音符时刻，无动态分配地合成有界的 16 kHz、16 位
  单声道 PCM。独立音频任务独占 BSP 音频读写，通过单槽信箱接收时间参数，
  与视觉播放器共享绝对起点；跳过过期拍点，不突发补拍，每次仅排入 20／35 ms 短音。
  编解码器实际延迟与声画对齐仍需设备测量。音量使用平方振幅曲线，硬件增益固定。
- `guitar_ui` 在 LVGL 串行访问下绘制自有状态快照。整个应用只创建一个常驻屏幕，
  不为页面创建遗留后台任务，也不分配全屏帧缓冲。右上角显示电量，不可用时显示 `--`。
- HTTP 任务先验证上传，再获取状态锁，写 Flash 前暂停，保存成功才替换活动曲谱。
  请求长度、接收重试和连接数均有限制；固定本地 Host 与编辑请求头阻止跨源表单提交。
- 保留原来的 24 KiB NVS／PHY／单 factory 分区。`guitar/score_v1` 使用包含
  终止符的 NVS blob，支持 4096 文本字节，不受 NVS 字符串 4000 字节上限影响。
  遇到错误不会自动擦除 NVS。保存数据损坏时保留原数据，使用练习谱并显示存储警告。
- 每份已解析曲库的注释共用一个 4097 字节的有界文本池，小节仅保存偏移。
  原有曲谱文本与 `score_v1` blob 存储格式保持兼容。
- 中文字体保存在 Flash。[资源说明](../assets/README.zh_CN.md)记录来源、精确范围、
  生成命令和许可证。位图索引要求启用 `CONFIG_LV_FONT_FMT_TXT_LARGE=y`。

## 验证与设备验收

激活 ESP-IDF 5.5.3 后运行仓库完整验证：

```sh
./tools/validate.sh
```

静态检查包含真实解析器、全部指型、30～120 各速度的播放边界、注释校验、10,000 组异常输入，
以及 HTTP/NVS 故障注入：分段接收、中断／超限请求、仅校验不写入、保存失败、
最大长度 blob、注释保存与重启加载、损坏数据和网络启动回滚。
音频测试覆盖全部 91 种速度、无重复／突发补拍、静音与音量、强弱音 PCM 区分、
暂停继续／曲终和任务／编解码器故障。也保留全部基线仓库／BSP 主机测试。
电量任务测试覆盖初始化／读取恢复、无电量计、非法 SOC、0%／100% 和有界重试间隔。
调速测试覆盖 1 BPM 步进及非 5 倍数速度的精确保留。
macOS 使用对应的链接器 dead-strip 参数，Linux 继续使用已有的分段垃圾回收参数。

额外的渲染与浏览器检查：

```sh
bash tools/test_guitar_ui.sh
# 一次性安装本地浏览器测试依赖：
npm install --prefix .tools --no-audit --no-fund playwright@1.58.2
.tools/node_modules/.bin/playwright install chromium
bash tools/test_guitar_web.sh
```

可通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定已安装的 Chromium。
浏览器测试使用实际 HTML、真实 C 解析器和本地测试服务器，不能证明实机 Wi-Fi／NVS 行为。
LVGL 测试使用真实 9.5 渲染器、24 KiB 内存池和 BSP 圆角遮罩，检查 16／24 px 字体描述符、
一个已知缺字反例、文本边界、全部页面、注释滚动渲染及 400 次重绘。
生成的 PPM／PNG 预览位于 `build/guitar-preview/`，不是设备实拍。

实机测试前必须报告 `Device tests: NOT RUN`。获准刷机后检查：

1. 启动、中文、长歌名／注释、指型可读性和五个页面。
   检查固定英文文案，以及启动后右上角 SOC 读取恢复。
2. ADC 按键的单击、双击、长按区分。
3. 30 和 120 BPM、八个半拍状态、四拍预备、滚动、暂停继续、手动跳转、曲终和反复选歌；
   每个八分音符有声、正拍强调清楚、各音量档位与完全静音。
4. 目标手机的热点发现、免密连接、DHCP、网页访问、断开重连后的刷新。
5. 正常与非法上传、播放时保存、反复保存 4096 字节曲谱、断电重启和保存中断恢复。
6. 手机连接时的最低堆内存、最大连续块、任务栈高水位、按键响应、声画对齐和节拍抖动。

交付验证生成的 `build/FoloToy-AI-Passport-full.bin`，从 **0x0** 刷写，
调试时使用匹配的 `build/firmware/<sha256>/manifest.json`、ELF 和 MAP。
合并刷写可能重置 NVS，需保留的数据应先导出。无需整片擦除或回读原固件。
构建成功和发现 USB 设备不代表刷机授权。详见[刷写策略](development/engineering/firmware-layout.zh_CN.md#烧录与已存数据)。
